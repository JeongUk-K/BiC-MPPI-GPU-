BiC-MPPI 실험 문제 정의 및 비용함수
=====================================

본 문서는 현재 저장소의 실제 GPU 구현을 기준으로 WMRobot(BARN) 실험과
6-DoF manipulator random-pose benchmark의 문제 정의, 비용함수, 제약조건 및
Guide MPPI 비용을 재현 가능한 형태로 정리한다.


1. WMRobot GPU 벤치마크
-----------------------

1.1 상태, 입력 및 동역학

WMRobot은 평면상 unicycle model로 정의한다.

    x_t = [p_x,t, p_y,t, theta_t]^T in R^3
    u_t = [v_t, omega_t]^T in R^2

연속시간 동역학은 다음과 같다.

    dot(p_x) = v cos(theta)
    dot(p_y) = v sin(theta)
    dot(theta) = omega

GPU rollout은 forward Euler 적분을 사용한다.

    x_{t+1} = x_t + Delta_t f(x_t, u_t)
    Delta_t = 0.1 s

제어입력은 다음 범위로 투영한다.

    0 <= v_t <= 1.0
    -pi/2 <= omega_t <= pi/2


1.2 실제 GPU rollout 비용

WMRobot의 실제 GPU rollout 비용은 horizon 전체에서 goal-state distance를
누적하고 마지막 상태의 goal distance를 한 번 더 더한다.

    J_WM(U) = sum_{t=0}^{T-1} ||x_t - x_g||_2
              + ||x_T - x_g||_2

따라서 running cost와 final cost는 다음과 같이 쓸 수 있다.

    l_WM(x_t, u_t; x_g) = ||x_t - x_g||_2
    phi_WM(x_T; x_g)    = ||x_T - x_g||_2

여기서 사용되는 상태 거리는

    ||x_t - x_g||_2
      = sqrt((p_x,t-p_x,g)^2
             + (p_y,t-p_y,g)^2
             + (theta_t-theta_g)^2)

이다. 각도 오차는 [-pi, pi)로 wrap하지 않으며, raw heading difference를
사용한다. GPU kernel에는 명시적인 control-effort 항이나 해당 가중치가 없다.

WMRobotMap 클래스에는 q(x,u)=||u||_2가 선언되어 있지만, 현재 GPU forward
rollout kernel은 이 stage cost를 호출하지 않는다. 따라서 논문의 재현 가능한
문제 정의에는 위의 실제 GPU 목적함수를 사용해야 한다.


1.3 충돌 처리

rollout의 초기 상태 또는 예측 상태 중 하나라도 occupancy-grid collision이면
해당 trajectory의 비용 전체를 다음 값으로 덮어쓴다.

    J_WM(U) = 1.0e8

따라서 collision cost는 각 시점에 더해지는 일반적인 additive penalty가 아니라
trajectory-level hard rejection이다.

BARN map의 grid resolution은 0.1 m이며, occupancy 값이 10.0인 cell을
collision으로 판정한다. 현재 WMRobot GPU collision kernel에는 별도의 로봇
반경 또는 footprint inflation이 없다.


1.4 벤치마크 설정

공통 설정:

    Delta_t                  = 0.1 s
    maximum MPC iterations  = 200
    sampling noise scale    = diag(0.6, 0.6)
    MPPI exponential factor = gamma_u = 10.0
    weight                  = exp[-gamma_u (J_i - J_min)]
    maps                    = BARN maps 0--299 (300 maps)
    map resolution          = 0.1 m

초기 및 목표 상태:

    x_init,1 = [0.5, 0.0, pi/2]^T
    x_init,2 = [2.5, 0.0, pi/2]^T
    x_goal   = [1.5, 5.0, pi/2]^T

따라서 기본 benchmark는 300 maps x 2 initial states = 600 trials이다.

MPPI, Log-MPPI 및 Cluster-MPPI:

    prediction horizon T = 100
    forward samples N     = 6000

BiC-MPPI:

    forward horizon Tf  = 50
    backward horizon Tb = 50
    forward samples Nf  = 6000
    backward samples Nb = 6000
    Guide samples Nr    = 3000 per connected reference

BiC-MPPI의 6000은 전체 sampling budget이 아니라 forward branch의 sample
수이다. 한 번의 BiC-MPPI 반복에는 기본적으로 forward 6000개와 backward
6000개가 사용되고, 각 connected reference마다 Guide rollout 3000개가
추가된다.

성공 조건은 다음과 같다.

    ||x - x_g||_2 < 0.1

또한 실행 trajectory에서 collision이 발생하지 않아야 한다.


1.5 WMRobot Guide MPPI 비용

연결된 forward/backward trajectory를 X_ref={x_ref,t}_{t=0}^{Tr}라 할 때,
현재 WMRobot GPU Guide rollout에서 실질적으로 사용되는 비용은 다음과 같다.

    J_guide_WM(U; X_ref)
      = ||x_Tr - x_g||_2
        + sum_{t=0}^{Tr} ||x_t - x_ref,t||_2

reference-tracking weight는 별도로 곱해지는 계수가 없으므로 1이다.
Guide rollout 중 collision이 발생하면 다음이 적용된다.

    J_guide_WM = 1.0e8

구현상 주의점:

GPU kernel은 loop 내부에서 goal distance를 임시로 누적하지만, rollout 종료 시
cost를 final goal cost로 재대입한다. 그 결과 이전에 누적한 goal distance가
사라진다. 따라서 현재 코드의 실질적인 Guide 비용은 final goal distance와
누적 reference-state deviation의 합이다. 논문의 Guide 식이 누적 goal cost까지
포함한다면 현재 WMRobot 코드와 논문 사이에 불일치가 존재한다.


2. Manipulator random-pose benchmark
-------------------------------------

2.1 상태, 제어입력 및 동역학

랜덤 pose benchmark는 공용 model/manipulator.h의 1차 velocity-control 모델이
아니라 별도의 12차원 torque-control 모델을 사용한다.

    x_t = [q_t^T, dot(q)_t^T]^T in R^12
    u_t = tau_t in R^6

각 관절의 동역학은 서로 독립인 second-order model로 근사한다.

    dot(q_i) = v_i
    dot(v_i) = (tau_i - d_i v_i - g_i sin(q_i)) / I_i

이는 다음 형태의 full rigid-body dynamics가 아니다.

    M(q) ddot(q) + C(q,dot(q)) dot(q) + G(q) = tau

사용되는 관절별 파라미터는 다음과 같다.

    joint       1      2      3      4      5      6
    -------------------------------------------------
    I_i       4.0    3.5    2.5    0.9    0.6    0.35
    d_i       3.5    3.2    2.5    0.8    0.5    0.35
    g_i       0.0    7.0    4.5    0.6    0.3    0.15

GPU prediction rollout은 forward Euler를 사용한다.

    x_{t+1} = x_t + Delta_t f(x_t, tau_t)
    Delta_t = 0.02 s

실제 receding-horizon 실행 state는 같은 Delta_t로 RK4 적분한 후 joint position과
velocity limits로 projection한다. 즉 GPU prediction은 Euler이고 closed-loop
execution은 RK4라는 차이가 있다.


2.2 Joint, velocity 및 torque limits

Joint position limits [rad]:

    q_min = [-6.28319, -6.28319, -3.1415,
             -6.28319, -6.28319, -6.28319]^T

    q_max = [ 6.28319,  6.28319,  3.1415,
              6.28319,  6.28319,  6.28319]^T

Closed-loop state projection에 사용하는 velocity limits [rad/s]:

    dot(q)_max = [2.0, 2.0, 2.0, 2.5, 2.5, 2.5]^T

실제 CUDA sampling control에 사용하는 torque limits는 다음과 같다.

    |tau_i| <= [18, 18, 14, 8, 6, 4]_i

CPU model에는 tau_max=[150,150,150,28,28,28]이 선언되어 있으나 GPU control
projection은 더 작은 [18,18,14,8,6,4]를 사용한다. GPU 결과 재현을 위한
논문 표에는 실제 CUDA limits를 기재해야 한다.


2.3 Regularization stage cost

기본 stage cost는 torque effort, joint velocity, joint-limit 및 workspace
obstacle 항으로 구성된다.

    l_reg(x_t, tau_t)
      = w_tau ||tau_t||_2^2
        + w_v ||dot(q)_t||_2^2
        + w_lim l_lim(q_t)
        + l_obs(q_t)

가중치는 다음과 같다.

    torque effort       w_tau = 1.0e-3
    joint velocity      w_v   = 2.0e-2
    joint-limit         w_lim = 20.0


2.4 Joint-limit penalty

각 관절에 대해

    c_i = (q_i,max + q_i,min) / 2
    r_i = (q_i,max - q_i,min) / 2
    z_i(q) = (q_i - c_i) / (0.85 r_i)

로 정의한다. Joint-limit penalty는 허용 범위 중심에서 전체 half-range의
85%까지 0이며, 이를 초과하면 quadratic penalty를 부여한다.

    l_lim(q)
      = sum_{i=1}^{6} [max(0, |z_i(q)| - 1)]^2

따라서 비용에 포함되는 전체 joint-limit 항은

    20.0 l_lim(q)

이다.


2.5 Workspace obstacle penalty와 collision 처리

Manipulator의 각 link를 두 joint position을 연결한 line segment로 근사한다.
GPU에서는 각 link에 대해 양 끝점을 포함한 5개의 균일한 sample points를
검사한다. 6개 link에 대해 총 30개의 점을 검사한다.

장애물 B는 axis-aligned bounding box(AABB)이며, 검사점 p의 link thickness를
반영한 signed clearance를 다음과 같이 정의한다.

    s(p,B) = d_signed(p,B) - r_link
    r_link = 0.045 m

여기서 d_signed는 AABB 바깥에서 양수, 내부에서 음수인 point-to-AABB signed
distance이다.

사용되는 margin은 다음과 같다.

    safe margin m_s = 0.10 m
    hard margin m_h = 0.02 m

각 link sample point와 obstacle pair에 대한 soft penalty는 다음과 같다.

                    { 1.0e4 ((0.10-s)/0.10)^2,  0.02 <= s < 0.10
    c_obs(s) =      {
                    { 0,                            s >= 0.10

전체 soft obstacle cost는

    l_obs(q)
      = sum_{links} sum_{5 sample points} sum_{boxes} c_obs(s(p(q),B))

이다.

다음 조건 중 하나를 만족하면 hard collision으로 판정한다.

    s(p,B) < 0.02 m
    또는
    p_z < 0

Hard collision이 발생하면 해당 trajectory의 다른 비용항과 관계없이 전체
비용을 다음 값으로 덮어쓴다.

    J = 1.0e8

CPU model configuration에는 w_workspace_obs=2.0e3 및 w_ground=2.0e4가
선언되어 있지만 실제 CUDA soft obstacle coefficient는 1.0e4이다. 또한 hard
collision은 최종적으로 trajectory-level 1.0e8 cost가 적용된다. 논문의 GPU
실험 재현 표에는 CUDA에서 실제 사용된 값을 기재해야 한다.


2.6 Goal-state cost

Goal-state cost는 joint configuration error, end-effector position error 및
joint-velocity error로 구성된다.

    Phi(x_t, x_g)
      = w_q ||q_t - q_g||_2^2
        + w_ee ||p_ee(q_t) - p_ee(q_g)||_2^2
        + w_qdot,g ||dot(q)_t - dot(q)_g||_2^2

가중치는 다음과 같다.

    terminal/running joint error       w_q      = 1500
    terminal/running EE position error w_ee     = 500
    terminal/running velocity error    w_qdot,g = 100

모든 benchmark target은 dot(q)_g=0으로 설정되므로

    Phi(x_t, x_g)
      = 1500 ||q_t-q_g||_2^2
        + 500 ||p_ee(q_t)-p_ee(q_g)||_2^2
        + 100 ||dot(q)_t||_2^2

이다.

코드에서는 이 함수를 terminal cost라고 부르지만, 실제 CUDA rollout에서는
terminal state에만 적용하지 않고 모든 prediction step에서 누적한다.


2.7 실제 forward rollout 목적함수

Manipulator의 실제 forward GPU objective는 다음과 같다.

    J_f(U)
      = sum_{t=0}^{T-1}
          [l_reg(x_t,tau_t) + Phi(x_t,x_g)]
        + Phi(x_T,x_g)

즉 goal-state cost Phi는 running goal cost와 final goal cost 양쪽에 동일하게
사용된다. 따라서 논문에서 Phi를 terminal cost로만 기술하면 실제 구현을
완전하게 설명하지 못한다.

Hard collision이 발생한 경우 위의 합산 비용 대신 J_f=1.0e8을 적용한다.


2.8 Backward rollout 비용

Backward branch는 x_g에서 시작하여 negative Euler integration을 수행하고
x_init을 backward goal로 사용한다. 개념적으로 다음 비용을 사용한다.

    J_b(U_b)
      = sum_{t=0}^{Tb-1}
          [l_reg(x_t^b,tau_t^b) + Phi(x_{t+1}^b,x_init)]
        + Phi(x_Tb^b,x_init)

마지막 backward state의 Phi는 loop 마지막과 종료 후에 중복으로 한 번 더
평가되는 구현 구조를 가진다. Backward rollout에서도 hard collision은 전체
비용 1.0e8을 적용한다.


2.9 Manipulator Guide MPPI 비용

연결 단계가 생성한 reference trajectory를

    X_ref = {x_ref,t}_{t=0}^{Tr}

라고 한다. Manipulator Guide MPPI rollout에서 사용하는 정확한 비용은 다음과
같다.

    J_guide(U; X_ref)
      = sum_{t=0}^{Tr-1}
          [l_reg(x_t,tau_t)
           + Phi(x_t,x_g)
           + w_ref ||x_t-x_ref,t||_2]
        + Phi(x_Tr,x_g)
        + w_ref ||x_Tr-x_ref,Tr||_2

여기서

    w_ref = 1.0

이다. Reference deviation은 squared norm이 아니라 12차원 state의 Euclidean
norm이다.

    ||x_t-x_ref,t||_2
      = sqrt(||q_t-q_ref,t||_2^2
             + ||dot(q)_t-dot(q)_ref,t||_2^2)

Guide rollout 중 hard collision이 발생하면 다음을 적용한다.

    J_guide = 1.0e8

각 reference에서 Guide MPPI weighted-average control을 얻은 후, 여러 connected
references 사이에서 최종 trajectory를 선택할 때는 다음 비용을 다시 계산한다.

    C_r = sum_{t=0}^{Tr} Phi(x_t,x_g)

이 최종 branch-selection 비용에는 torque, velocity, joint-limit, soft-obstacle
및 reference-deviation 항이 포함되지 않는다. 단, collision trajectory는
1.0e8로 rejection한다.

    number of possible scenarios = 16 x 15 = 240

각 initial 및 goal state의 velocity는 0이다.

    x_init = [q_init^T, 0^T]^T
    x_goal = [q_goal^T, 0^T]^T

2.11 Scenario obstacle 생성

각 initial-goal pair에 대해 end-effector midpoint를 계산한다.

    c_B = [p_ee(q_init) + p_ee(q_goal)] / 2

장애물은 이 midpoint를 중심으로 하는 AABB이며 기본 크기는 다음과 같다.

    width  = 0.07 m
    depth  = 0.07 m
    height = 0.11 m

구체적인 bounds는 다음과 같다.

    x_min = c_B,x - 0.035
    x_max = c_B,x + 0.035
    y_min = c_B,y - 0.035
    y_max = c_B,y + 0.035
    z_min = max(0.05, c_B,z - 0.055)
    z_max = max(z_min + 0.02, c_B,z + 0.055)

초기 pose와 goal pose 자체는 qdot=0인 상태로 사용한다.


2.12 현재 기본 실행 scenario

코드가 생성할 수 있는 전체 ordered pairs는 240개지만, 현재 환경변수 override가
없는 기본 실행은 다음 세 개의 representative scenarios만 선택한다.

    scenario 0   : home_mid       -> detour_high
    scenario 129 : left_high      -> right_high
    scenario 239 : front_right_mid -> front_left_mid

따라서 논문에서 240-pair random benchmark라고 기술하려면 실제 실행 당시
MANIPULATOR_BENCHMARK_SCENARIO_IDS 또는 MANIPULATOR_BENCHMARK_SCENARIOS 설정과
결과 CSV의 scenario 수를 확인해야 한다.


2.13 Manipulator solver 설정

MPPI, Log-MPPI 및 Cluster-MPPI:

    Delta_t                 = 0.02 s
    forward horizon T       = 90
    forward samples N       = 1024
    gamma_u                 = 0.0015
    sampling noise scale    = [4.5, 4.5, 3.8, 2.2, 1.8, 1.2]

BiC-MPPI:

    Delta_t                 = 0.02 s
    forward horizon Tf      = 45
    backward horizon Tb     = 45
    forward samples Nf      = 1024
    backward samples Nb     = 1024
    Guide samples Nr        = 1024
    gamma_u                 = 0.0015
    sampling noise scale    = [4.5, 4.5, 3.8, 2.2, 1.8, 1.2]

Cluster-MPPI와 BiC-MPPI의 현재 random benchmark는 K-means를 사용한다.

    number of K-means clusters = 5
    maximum K-means iterations = 100
    convergence threshold      = 1.0e-6

MPPI trajectory weights는 다음과 같다.

    w_i = exp[-gamma_u (J_i-J_min)]
          / sum_j exp[-gamma_u (J_j-J_min)]


2.14 Warm start 및 receding-horizon 실행

초기 forward nominal controls는 waypoint와 goal을 순차적으로 추종하는 PD torque
sequence로 생성한다. Horizon의 앞 절반은 선택된 collision-free waypoint를,
뒤 절반은 goal을 reference로 사용한다.

    tau_t = K_p (q_ref,t-q_t) - K_d dot(q)_t
    K_p = 18
    K_d = 7

각 MPC iteration 후에는 최적 control sequence를 한 step shift하여 다음 nominal
sequence로 사용한다. BiC-MPPI backward nominal controls는 매 iteration 현재
state와 goal 사이의 PD torque sequence로 다시 생성한다.


2.15 성공 조건

다음 세 조건을 모두 만족하면 reached로 판정한다.

    ||q-q_g||_2 < 0.03 rad
    ||p_ee(q)-p_ee(q_g)||_2 < 0.05 m
    ||dot(q)||_2 < 0.20 rad/s

최종 benchmark success는 reached 조건에 더해 실제 executed trajectory에서
workspace collision count가 0이어야 한다.

    success = reached AND (collision_count == 0)

Maximum receding-horizon iterations는 scenario당 200이다.


3. 비용 및 제약 파라미터 요약
-------------------------------

WMRobot:

    running goal-distance weight       1
    final goal-distance weight         1
    control-effort weight              없음(GPU kernel 기준)
    Guide reference-deviation weight   1
    collision trajectory cost          1.0e8

Manipulator:

    torque-effort weight               1.0e-3
    joint-velocity weight              2.0e-2
    joint-limit weight                 20
    running/final joint-goal weight    1500
    running/final EE-goal weight       500
    running/final velocity weight      100
    GPU soft-obstacle coefficient      1.0e4
    obstacle safe margin               0.10 m
    hard collision margin              0.02 m
    link radius                        0.045 m
    Guide reference-deviation weight   1
    hard collision trajectory cost     1.0e8


4. 논문 작성 시 반드시 명시할 구현상 차이
-----------------------------------------

(1) WMRobot의 클래스 정의에는 ||u||_2 stage cost가 있지만 현재 GPU rollout은
    이를 사용하지 않는다.

(2) WMRobot Guide kernel은 loop에서 누적한 goal distance를 종료 시 final goal
    cost로 덮어쓴다. 따라서 실제 비용은 final goal distance와 reference
    deviation의 합이다.

(3) Manipulator의 goal cost는 이름과 달리 terminal state에서만 사용되지 않고
    GPU rollout의 모든 prediction step에서 누적된다.

(4) Manipulator CPU model의 workspace weight는 2.0e3이지만 실제 CUDA soft
    obstacle coefficient는 1.0e4이다.

(5) Manipulator CPU model의 torque limit 선언은
    [150,150,150,28,28,28]이지만 CUDA sampled controls는
    [18,18,14,8,6,4]로 clipping된다.

(6) Manipulator GPU prediction은 Euler integration을 사용하지만 실제 executed
    state update는 RK4와 state projection을 사용한다.

(7) Manipulator random-pose benchmark는 240개의 ordered pairs를 생성할 수
    있으나 현재 기본 실행은 scenario 0, 129, 239의 세 개만 선택한다.

위 차이를 그대로 유지하여 기존 실험을 재현한다면 논문에 명시해야 한다.
반대로 논문에서 하나의 통일된 수학적 문제를 제시하려면 CPU/GPU 비용,
제약조건 및 적분 방식을 먼저 일치시킨 후 실험을 다시 수행해야 한다.
