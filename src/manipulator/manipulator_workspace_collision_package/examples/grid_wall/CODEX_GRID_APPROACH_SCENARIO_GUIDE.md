# Codex Guide: Free-Opposite Grid Approach Scenario

## 1. Scenario change

The previous task sampled two insertion cells:

```text
init_insert -> init_retract -> goal_retract -> goal_insert
```

The new task is:

```text
free_opposite -> free_aligned -> goal_retract -> goal_insert
```

Meaning:

- The initial state is a free-space posture.
- The wrist/tool side is intentionally flipped away from the grid.
- The goal is one randomly selected grid insertion cell.
- The planner should reorient in free space, approach the grid, then insert.

## 3. Key implementation details

### Free-opposite pose

The free pose is selected from hard-coded candidates:

```cpp
makeFreeOppositePoseCandidates()
selectFreeOppositePose()
```

This encodes "opposite-facing" as a joint posture. It is not a strict SO(3) orientation constraint.

### Aligned free pose

The aligned free pose is generated by IK for:

```cpp
p_free_aligned = [x_free_align, goal_y, goal_z]
```

with default:

```cpp
x_free_align = -0.06
```

### Warm-start

Forward:

```text
free_opposite -> free_aligned -> goal_retract -> goal_insert
```

Backward:

```text
goal_insert -> goal_retract -> free_aligned -> free_opposite
```

## 4. If build fails

### Missing header

If:

```text
fatal error: manipulator_grid_approach_task.h: No such file or directory
```

place the header in the same include directory as `manipulator_grid_wall_task.h`.

### Missing function from grid wall header

If symbols such as these are missing:

```cpp
solveCollisionFreePositionIK
makeGridCellPoseSet9
makeGridWallWorkspaceBoxes
```

you are using the older grid-wall header. Replace it with the fixed version.

### `endEffectorPosition` signature mismatch

The code assumes:

```cpp
model.endEffectorPosition(x)
```

where `x=[q;qdot]`.

If your model expects `q`, patch calls to:

```cpp
model.endEffectorPosition(x.head(ManipulatorDynamicsModel::kDof))
```

### `inWorkspaceCollision` missing

The scenario requires:

```cpp
model.inWorkspaceCollision(x)
```

If missing, add it to `ManipulatorDynamicsModel` or route it through your existing collision checker.

## 5. Runtime checks

The program prints:

```text
free_opposite_coll
free_aligned_coll
goal_retract_coll
goal_insert_coll
```

All should be zero for paper-quality runs.

If `free_opposite_coll=1`:

- Try another candidate in `makeFreeOppositePoseCandidates`.
- Reduce `model.link_radius`.
- Move wall away from base or implement distal-link-only collision for grid walls.

If `free_aligned_coll=1`:

- Increase `x_free_align`, for example:
  ```cpp
  x_free_align = 0.02;
  ```
- Relax grid wall thickness:
  ```cpp
  wall_thickness = 0.020;
  ```

If `goal_insert_coll=1`:

- The IK cell pose is invalid.
- Use the fixed collision-free IK version of `manipulator_grid_wall_task.h`.
- Consider excluding invalid goal cells from sampling.

## 6. If the robot moves sideways through the wall

The collision checker is not being applied consistently.

Check:

1. `n_ws_boxes == 4` in GPU upload.
2. CPU and GPU use identical AABB boxes.
3. CPU and GPU FK use the same DH parameters.
4. Workspace collision is checked in:
   - forward rollout
   - backward rollout
   - Guide MPPI rollout
5. `model.link_radius == cc.link_radius`.

## 7. If it approaches but does not insert

The final target is too weak or the terminal condition is too strict.

Try:

```cpp
model.w_terminal_ee = 6.0e3;
model.w_terminal_q = 2.0e1;
ee_tol = 0.055;
```

Use end-effector error as the main success metric. Joint error is diagnostic.

## 8. Paper wording

Safe wording:

> We evaluate BiC-MPPI on a free-space-to-grid insertion benchmark. The arm starts from a free-space posture with the wrist/tool side flipped away from the grid, then approaches and inserts into one of nine grid cells separated by AABB walls.

Do not claim:

- exact tool orientation control
- full contact-rich insertion
- exact mesh collision
